## What happened

Your Mac has the **.NET 10 runtime** (10.0.14) installed, but the project targeted **.NET 8** — the build succeeded (the .NET 10 SDK can compile net8.0), but at launch the debugger found no 8.0 runtime to run it. That's the "exit code 150" you saw.

## The fix (already applied in the updated zip)

I retargeted the project to .NET 10, which matches what you have — nothing new to install:

- `TodoApi/TodoApi.csproj` — `<TargetFramework>` is now `net10.0`, and the EF Core packages are bumped to 10.0.14, the current stable release [nuget](https://www.nuget.org/packages/Microsoft.EntityFrameworkCore.sqlserver/)
- `.vscode/launch.json` — the debugger's `program` path now points to `bin/Debug/net10.0/TodoApi.dll`
- README — prerequisites and troubleshooting updated for this error

To apply it to your existing copy: unzip over your folder (or manually make those three small edits), then clean the stale build output before pressing F5:

```bash
cd TodoApi
rm -rf bin obj

or

rm -rf bin
rm -rf obj


dotnet restore
```
